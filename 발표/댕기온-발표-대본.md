## ❓ Q&A 예상 질문 & 답변

**Q1. 룰베이스는 AI가 아니지 않나요?** ★가장 유력
> “AI는 머신러닝만을 뜻하지 않습니다. 규칙으로 지식을 표현해 추론하는 전문가 시스템은 AI의 정통이고 의료 진단 등 고위험 도메인에서 지금도 쓰입니다. 저희는 ML을 못 써서가 아니라, **설명가능성·콜드스타트·안전 책임** 세 조건에서 룰베이스가 더 적합하다고 판단해 선택했고, 데이터가 쌓이면 ML을 얹도록 이미 설계했습니다.”

**Q2. 그럼 그냥 if문 아닌가요?**
> “단순 조건문이 아니라 수의학 문헌 기반 임계값 + 견종 388종 체질 데이터 + 치명요인 등급 override + 구간 선형화를 갖춘 도메인 지식 엔진입니다. 실제로 운영 데이터 노이즈에 맞춰 룰 강건성을 개선한 엔지니어링 사이클도 돌았습니다.”

**Q3. ML은 언제 쓰나요? / 데이터는 있나요?**
> “산책 후 체감 피드백 수집 파이프를 이미 코드로 구축해 뒀습니다. 데이터가 쌓이면 견종 군집화 → 피드백 가중치 학습 순으로 확장합니다.”

**Q4. 왜 서비스를 3개로 나눴나요? 관리가 복잡하지 않나요?**
> “백엔드는 HTTP 호출만 하고 AI는 Python으로 끝까지 소유해 ML 확장을 열어두려는 의도였습니다. 비용도 로컬 개발은 0원, 한 호스트에 합치면 추가 서버비도 거의 없어 ‘2개=2배’ 오해는 실측으로 해소했습니다.”

**Q5. (아키텍처의) HTTP/1.1이 보이던데 HTTPS 아닌가요?**
> “사용자가 접하는 구간은 전부 HTTPS입니다. 내부 백엔드↔AI 호출을 HTTP **버전** 1.1로 고정한 건, HTTP/2에서 uvicorn 바디 유실 이슈가 있어 우회한 것으로, 암호화(HTTPS)와는 다른 축입니다.”

**Q6. 정확도는 어떻게 검증했나요?**
> “수의학 문헌 기준값으로 회귀 테스트 36개를 만들어 룰 변경마다 통과를 확인했고, 실제 부산 날씨로 e2e 검증했습니다. 정량 정확도는 피드백 데이터가 쌓이는 Phase 2에서 측정할 계획입니다.”

**Q7. 실시간 GPS는 왜 없나요?**
> “웹 우선이라 타이머+경로 입력 방식으로 구현하되, 거리 계산 로직(haversine)은 이미 넣어둬서 모바일 GPS로 바로 확장 가능합니다.”
