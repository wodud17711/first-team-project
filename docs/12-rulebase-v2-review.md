## 0. 결론 (요약)

- **v1.3 가중치는 변경하지 않는다(보류).** 근거: 실측 피드백 표본 0건 → 수집 설계 §5 가드(셀당 n≥30)를 만족하지 못해, 데이터 기반 튜닝의 전제가 성립하지 않는다.
- **수집 파이프는 지금 가동한다.** 설계(`docs/11`)와 쿼리(`feedback_divergence.sql`)를 정본화(커밋)해, FE 피드백 카드 배선·실사용이 시작되면 즉시 분석 가능한 상태로 둔다.
- **시나리오 검증으로 FN(과소경보) 후보 3건을 식별**했다(아래 §2). 데이터가 쌓이면 가장 먼저 검증할 대상으로 등재한다 — 지금은 "가설"이지 "변경"이 아니다.

> 한 줄: **변경 보류 + 근거 문서화 + 수집 가동 + v2 후보 등재.** (카드 완료기준 충족)

## 1. 현 룰베이스 상태 (v1.3)

`ai/scripts/validate_rules.py`로 (견종 7종 × 날씨 10종) 핵심 조합을 검증한 결과(2026-06-15):

- **룰 커버리지 20/21 발화.** 미발화 1건은 `GROUND_TEMP_HIGH`(지면 40~50℃)로, 검증 시나리오에 해당 지면온도 케이스가 없었을 뿐 단독 프로브("지면 42℃ → 주의")에서는 정상 동작한다. → 룰 결함 아님, **검증 시나리오 갭**.
- **복합 상황 등급 분리 양호.** 폭염×단두종(0점 위험), 폭염×내열약(0점 위험), 한겨울×내한약(55점 주의), 쾌적(100점 안전) 등 의도대로 분리된다.
- **치명 요인 override 정상.** 지면 50℃(화상)→최소 위험, 지면 40~50℃·미세먼지 매우나쁨→최소 주의 보장(점수만으로 임계를 못 넘는 단일 치명요인 보정, v1.3).

## 2. FN(과소경보) 후보 — v2 1순위 검증 대상

수집 설계 §2 매트릭스에서 **과소경보(모델 '안전'인데 사용자가 힘듦, FN)** 는 안전 직결이라 가장 위험한 오류다. 시나리오 검증에서 **단일 중간위험 요인이 임계(70)를 못 넘어 '안전'으로 표기**되는 패턴이 보였다(보통견 기준, 해당 요인만 있을 때):

| 단독 요인 | 발화 룰(감점) | 결과 | 관찰 |
| --- | --- | --- | --- |
| 체감 33℃ | `FEELS_HOT`(-20) | **80점 안전** | 체감 33℃는 폭염주의보 수준 — '주의' 후보 |
| 자외선 지수 9 | `UV_VERY_HIGH`(-15) | **85점 안전** | 매우 강함(8~10) 단독은 등급 영향 없음 |
| 미세먼지 나쁨(pm10 100) | `PM_BAD`(-15) | **85점 안전** | '나쁨'인데 안전 — 호흡기 취약견 고려 시 약함 |

- 공통 원인: 단일 중간위험은 감점(-15~-20)만으로 임계 70을 못 넘는다. v1.3가 치명 요인(화상·미세먼지 매우나쁨)에만 `LEVEL_OVERRIDES`를 둔 것과 같은 구조적 한계.
- **가능한 v2 방향(데이터 검증 후)**: ① 중간위험 요인 감점 상향, ② 또는 `LEVEL_OVERRIDES`에 "체감 33℃↑ / 미세먼지 나쁨↑ → 최소 주의" 추가. **둘 다 지금은 적용하지 않는다**(아래 §3).

---

## 3. 왜 지금 바꾸지 않는가

- **수집 설계 §5 가드**: 셀당 표본 n≥30 전엔 그 칸 근거로 룰 수정 금지(노이즈 과적합 방지).
- **현재 실측 피드백 = 0건**: 산책 종료 피드백(`walks.user_feedback`)의 구조화 수집이 FE 카드 배선(정선혜) + 실사용 후에야 시작된다. 데모 단계라 사용자 표본이 없다.
- §2 후보는 도메인 상식상 그럴듯하지만, **임계값을 얼마로 내릴지**는 체감 데이터 없이 정할 수 없다(33℃? 31℃? intensity 가중?). 감으로 바꾸면 FP(과대경보=겁쟁이 모델)로 역전될 위험.

## 4. 수집 파이프 가동 (이번 커밋)

- `docs/11-walk-feedback-collection.md` — 수집 설계 정본(태깅 스키마·괴리 매트릭스·쿼리·가드).
- `ai/scripts/feedback_divergence.sql` — 읽기 전용 수집 쿼리 4종(산책별 괴리 뷰 / level×thermal 집계 / FN 체감온도 밴드 / 단두종 세그먼트).
- **착수 조건**(설계 §7 체크리스트): FE 종료 피드백 카드가 `userFeedback`에 `{"thermal":"HOT|OK|COLD",...}` JSON을 실어 보냄 → 표본 누적 모니터 → 셀당 n≥30 도달 시 §2 후보 검증.

## 5. 후속 (데이터 누적 후)

1. `feedback_divergence.sql` [2] 매트릭스로 level×thermal 분포 산출 → FN/FP 비율 확인.
2. **FN 우선**: §2 후보(체감·자외선·미세먼지)부터 [3] 체감온도 밴드·[4] 단두종 세그먼트로 어느 구간에서 터지는지 확인.
3. **1축씩** 임계/감점 조정 → 재수집으로 효과 확인(A/B처럼). 한 번에 하나만.
4. 변경 시 `walk_risk.py` 버전업(v1.4+) + 이 문서 갱신.

## 6. 발표(Week 6) 관점 (선택)

실데이터가 끝내 부족하면, **의도된 괴리 케이스를 시드**해 "수집 → 괴리 분석 → 룰 튜닝" 루프를 시연하는 것도 유효하다(카드 "조건부"). 데이터 기반 개선 루프를 **설계해 두었다는 것** 자체가 룰베이스 서비스의 차별점이다.
